# おしゃべりnote 0.1.1 開発中

noteのホームをOllamaチャットに置き換える、PC版Chrome・Edge・Firefox向けの非公式拡張です。ひきこもりnote v0.3.0のひとみしりモードを基にしています。

0.1.1は未公開の試作です。公開済み0.1.0の配布物は既存Releaseを利用してください。

## 0.1.1の試作：同じ著者の他記事要約

新しく完了した要約を著者ID→記事IDで保存し、再要約時は上書きします。感想とその区間の自由入力には、対象記事を除く同じ著者の保存済み要約をタイトルの自然順で添えます。連作であると決めつけず、関連がある場合だけ参考にするよう指示します。要約・修正点・引用列挙には他記事要約を付けません。別著者の同じ表示名は同一人物として扱いません。

0.1.0の過去の回答は自動登録せず、記事を再要約してから蓄積します。記事が変わった場合は旧要約を無効にし、ブラウザ終了後は残しますが、記事タブの「新しい会話」と接続先変更では要約Mapも削除します。保存全体8MiBと既存の送信上限を維持し、要約を黙って間引きません。詳しくは[0.1.1の試作仕様](spec/ARTICLE_AUTHOR_SUMMARIES_SPEC_0.1.1.md)を参照してください。

## 導入

1. [GitHub Release](https://github.com/ruminar/OshaberiNote/releases/tag/0.1.0)から対象ブラウザのZIPをダウンロードし、展開します。ソースから生成する場合は PowerShellから `.\scripts\package.ps1` で構文・自動テストと両ブラウザの配布生成を実行できます。
2. Chrome / Edgeの拡張管理画面で開発者モードを有効にし、ZIPの展開先（ソースから生成した場合は `dist/OshaberiNote-0.1.1-chromium`）を「パッケージ化されていない拡張機能」として読み込みます。
3. Firefoxでは `about:debugging#/runtime/this-firefox` →「一時的なアドオンを読み込む」から ZIPの展開先の `manifest.json`（ソースから生成した場合は `dist/OshaberiNote-0.1.1-firefox/manifest.json`）を指定します。Firefox 140以上が必要です。Androidは対象外です。
4. ひきこもりnoteは無効にして、Ollamaを起動します。拡張アイコンから専用ホームの「LLMの設定」を開き、「接続・再試行」で接続先へのアクセスを許可し、モデルを選択します。
5. メッセージを入力して「送信」を押します。Ctrl+Enterで送信、Enterで改行します。IME変換中はショートカットで送信しません。送信後は入力欄へフォーカスを戻し、応答を待ちながら次のメッセージを書けます。次の送信は生成終了後に可能です。中止・新しい会話・再読み込み・接続先変更も確認してください。

Ollama未接続でも、お気に入り・設定や通常のnote閲覧は利用できます。GitHubで配布するZIPは手動読み込み用です。ブラウザストアへの登録とFirefox向け署名は行っていません。

設定で「システム・ダーク・ライト」を選べます。初期値の「システム」はOS・ブラウザの配色設定に追従し、保存した選択は各ホーム画面と再読み込み後にも反映します。

## 接続とプライバシー

初期接続先は `http://127.0.0.1:11434` です。接続先は独立した「LLMの設定」から変更できます。変更を適用すると会話・未送信入力・モデル選択・システムプロンプトを初期化します。HTTPのLAN接続は暗号化されません。認証付きURL・APIのリダイレクトには対応しません。

Firefoxでは接続ボタンからホスト権限と会話送信の任意同意（`personalCommunications`）を要求します。拒否・取消時には接続しません。[Firefox公式の同意仕様](https://extensionworkshop.com/documentation/develop/firefox-builtin-data-consent/)に基づく宣言です。

接続許可は設定したホストについてのみ要求します。ブラウザのホスト権限はポート単位の制限ではないため、実際の通信先を保存済みURLと `/api/tags`・`/api/chat` に限定しています。Manifestの任意ホスト権限は接続先選択のための宣言であり、全ホストの権限を自動取得しません。

ブラウザから接続できない場合は、Ollama側の `OLLAMA_ORIGINS` に専用ホームの実際のオリジン（`chrome-extension://拡張ID` または `moz-extension://実行時UUID`）を追加し、Ollamaを再起動してください。実際のオリジンは専用ホームのアドレスから確認できます。すべての拡張やすべてのWebサイトを許可する設定は推奨しません。LAN接続ではOllama側の待受アドレスとファイアウォールも利用者が設定してください。

モデル一覧の取得が成功しても、Origin付きの会話POSTだけがHTTP 403で拒否される場合があります。モデル一覧の取得は会話送信の成功を保証しません。403の場合は「LLMの設定」に、その拡張の実際のOriginとWindows向けの起動用コマンドを表示します。タスクトレイのOllamaを終了し、Ollamaを動かしているPCのPowerShellでそのコマンドを実行してから、拡張で再試行してください。コマンドは既存の許可先を保持して当該Originを追加し、そのPowerShellのプロセス環境だけに設定します。環境変数の永続設定・待受アドレス・他のアプリの設定は変更しません。

通常会話・タグ提案では入力・完了済み履歴・システムプロンプトを送信します。記事タブの要約・感想・修正点・引用列挙は対象記事1件で開始し、自由入力だけは同じ会話区間の過去の依頼・回答を含めます。他の記事の本文や他区間の会話は送りません。感想とその続きに限り、同じ著者の他記事要約も参考情報として送ります。「タグの提案」の会話では、お気に入り全4グループの登録済みタグ名も送信します。note本文・Cookie・認証情報を自動送信せず、AIによる操作やスクリプト実行は行いません。会話は暗号化せずブラウザの拡張保存領域に保持します。共用PCでは内容に注意し、「新しい会話」で削除してください。

ローカルOllamaでもクラウドモデルを使うとOllama側から外部へ通信します。完全ローカル運用では利用者が `OLLAMA_NO_CLOUD=1` またはOllamaの `server.json` の `disable_ollama_cloud: true` を設定してOllamaを再起動してください。拡張からOllamaの環境設定は変更しません。

参考：[Ollama公式FAQ](https://docs.ollama.com/faq)、[Chat API](https://docs.ollama.com/api/chat)、[Chromeの任意権限](https://developer.chrome.com/docs/extensions/reference/api/permissions)。

## noteアイコン

拡張ON時は、note公式ヘッダーのアイコンから常に「おしゃべり」へ戻ります。ブラウザバックへの差し替え機能と設定は削除し、旧設定JSONの該当項目も無視します。Ctrl／Meta＋クリックや中クリックでは新しいタブで「おしゃべり」を開き、元のページは残します。Shift＋クリックなどの別ウィンドウ操作もブラウザ標準に従います。ロゴ横の歯車から通常の設定画面を開けます。拡張OFFではnote本来の動作に戻ります。専用ホームの「前の画面に戻る」ボタンは引き続き利用できます。

## 長文入力と履歴

メッセージは最大200,000文字まで入力でき、記事本文を手動で貼り付けられます。記事ページからの取り込みは「記事について」を利用できます。

OllamaのチャットAPIは会話履歴を自動保存しないため、通常会話とタグ提案では続きに必要な履歴を毎回アドオンから送信します。記事タブの操作は独立して送信し、自由入力だけ全画面で共有する最新区間の完了済み履歴を使います。通常会話・タグ提案は直近10往復・最大2MiBを保持します。「記事について」は往復数の上限を設けず、履歴最大2MiB・本文を含む全体最大8MiBまで保持します。容量上限を超えた履歴は古い往復から自動で整理します。通常会話・タグ提案の送信は最大256,000文字に収まる直近の完了済み往復を使い、今回の入力とシステムプロンプトを優先します。保存・送信対象から外した件数を画面に表示し、履歴量のために「新しい会話」を強制しません。

要約のための追加生成は行いません。通常会話・タグ提案ではOllama側の切り捨てを許可しますが、記事タブでは切り捨てを禁止し、モデルに収まらなければエラーにします。拡張はモデルのコンテキスト長を変更しません。詳細は[公式Chat API](https://docs.ollama.com/api/chat)と[Ollamaの履歴調整処理](https://github.com/ollama/ollama/blob/main/server/prompt.go)を参照してください。

単発の入力上限を超えた場合は、その送信だけを拒否して入力を保持します。短く直せば再読み込みなしで再送できます。通信や保存に失敗した際の自動再送は行いません。

## LLMの設定

「LLMの設定」に接続URL・接続／再試行・モデル選択・システムプロンプトをまとめています。送信内容、未接続時の確認事項、クラウド利用、履歴保持と整理件数、Origin許可の説明もここで確認できます。「おしゃべり」は会話と送信・中止を中心に表示します。通常チャット用のプロンプトは最大8,000文字で、保存した本文を毎回の会話送信の先頭にsystemメッセージとして一度だけ置きます。空欄で保存すると追加しません。効き方はモデルによります。

通常用プロンプト変更の保存時には、条件を揃えるため「通常の会話」の履歴と未送信入力を初期化します。他の会話タブは維持します。保存前に確認し、取消時は保持します。「新しい会話」ではプロンプトを維持し、接続先変更時は空に戻します。保存していないプロンプトは送信しません。内容は設定JSONにも含まれます。

## 発言を順に読む

会話欄の上の「△ 前の発言」「▽ 次の発言」で、自分とAIの各発言の先頭へ順番に移動できます。手動スクロール後は現在位置を基準に移動し、中央に「現在 / 全体」の発言数を表示します。初回も含め、送信受付で今回の自分の発言（例：7 / 8）、回答完了で今回のAIの発言（8 / 8）の先頭へ合わせます。生成途中は位置を保ち、回答末尾へ追従しません。初回も送信受付で1 / 2、回答完了で2 / 2へ合わせます。ただし「記事について」の要約・感想・修正点・引用列挙は、完了後も記事タイトルボタンのある自分の発言位置に留めます。自由入力の回答は通常どおりAI発言へ移動します。短い回答にも先頭合わせ用の余白を設け、余白の計算には会話欄のCSS上限を使って高さの往復を抑えます。入力中・送信拒否・中止・失敗ではAIの完了位置へ移動しません。

## メッセージのコピー

自分の発言とAI回答の右上にある「コピー」で、そのメッセージの本文だけをクリップボードへコピーできます。改行・余白・タグ表記は原文を保持し、話者名・操作ボタン・システムプロンプトは含めません。生成中のAI回答と空の応答はコピーできません。中断した回答は、表示されている本文があればコピーできます。失敗時はその場で案内し、会話は変更しません。

## AIのタグ提案から検索・登録

上部の「通常の会話」「タグの提案」「記事について」は、会話と履歴を分離したタブです。初めて使うときは「通常の会話」を表示し、以後は最後に選んだ会話タブを保存して、開き直し・再読み込み時に復元します。復元だけでは質問を送信しません。別のタブへ切り替えても元の履歴を消さず、戻るとその会話を復元します。未送信入力もページを開いている間はタブごとに保持します。左右矢印・Home・Endでも切り替えられます。

「タグの提案」を初めて開いたときだけ、「noteで面白そうなタグを提案してください。」を初回入力にします。接続・モデル選択済みなら送信し、未接続なら入力欄に置いて送信を待ちます。再選択や再読み込みでは再送しません。専用システムプロンプトv1.2と全4グループの最新タグ名を、毎回のリクエストに付与します。作者・マガジン・メンバーシップは含めません。

「新しい会話」は選択中のタブだけ初期化し、種類は変えません。生成中に切り替えると、その画面の生成を中止して未完了扱いにします。生成は全タブ・全画面を通じて1件に制限し、他の画面で実行中の生成を切替だけで止めません。通常用プロンプトや他タブの履歴は送信へ混ぜません。専用プロンプトは履歴へ表示・重複保存しません。

既存の単一会話は種類に対応するタブへ移行します。設定移行JSONには、タブの会話・選択状態・下書きを含めません。記事の要約・感想・修正点・引用列挙は3つ目の「記事について」タブで扱います。

登録済みタグがある初回は、関連する新しいタグを過半数として提案し、理由に元の登録済みタグとのつながりを添えるよう指定しています。幅広い分野からの提案は、登録タグがない場合や明示的な分野変更時を中心にします。

「他は何がありますか？」などの追加依頼では、直前の話題と利用者が示した関心に関連する別候補を優先します。「別の方向で」と明示した場合に分野を広げます。AIが提案しただけの分野を利用者の好みと見なさないよう指定しています。応答への反映はモデルにも依存します。

完了したAI回答の `**要点整理**` は太字で表示します。行頭の `* ` は箇条書きとして表示し、字下げされた項目は入れ子にします。箇条書き内の太字やタグ操作にも対応します。太字内のタグも操作でき、コピー・保存・次回送信には `**` を含む原文を使用します。HTMLは解釈せず、閉じていない記号や改行をまたぐ強調は文字として残します。

回答が完了すると、`[#週末の過ごし方]` のようなタグ表記がボタンになります。押すと「このタグで検索」と、①～④の各お気に入りグループへの登録を選べます。検索は新しいタブで開き、元のダイアログは開いたまま残します。結果を確認して戻った後、そのままグループへ登録できます。登録済みのグループは無効表示します。グループ名は現在の設定を使います。

生成途中・中断した回答や利用者の入力は変換しません。AIの提案だけで自動登録することはなく、回答原文は変更せず保存・送信します。初版では100文字以内のタグを回答あたり100個まで操作化し、それ以外は文字として残します。

## 記事について

公開記事ページの左メニューにある「この記事を要約」を押すと、閲覧できるタイトル・著者名・本文を取り込みます。右隣がこの拡張のおしゃべり画面なら読み込み直さず再利用し、それ以外の場合は同じウィンドウの右隣へ新しいおしゃべり画面を開きます。開いたタブへは切り替えず、記事を表示したままにします。既存の会話を残したまま要約依頼を追加します。PC幅1100px以上で左側の余白と既知の記事構造を確認できる場合に表示し、本文を囲むdata-note-keyとURLの記事ID、同じ記事領域にあるタイトルの対応を確認できないときは送信しません。有料の閲覧不可部分・コメント・メニュー・認証情報は取得しません。記事を開くだけでは取り込みません。

その上に「◀ 前の記事」「次の記事 ▶」を表示し、同じタブで前後の記事へ移動できます。画面をスクロールせずに使えるよう、note自身が記事末尾で使う読み取り専用APIから前後の記事名・URLを取得します。取得は表示中の記事・マガジンごとに一度で、認証情報を付けずに要求します。失敗時の自動再送は行いません。記事末尾の公式リンクが読み込まれていればそちらを優先し、本文中のリンクや外部サイトは使いません。存在しない側や取得できない場合は無効表示です。取得した前後リンクは画面内だけで保持し、会話・記事Mapへ保存せず、LLMにも送りません。

その下の「記事全文を取得」は、タイトル・著者名・投稿日・元記事URL・本文をクリップボードへコピーします。本文は要約に使うものと同じ取得処理によるもので、リンクや取得できるリンクカード情報も含みます。投稿日は本文外の表示中の日付情報から確認できる場合だけ設定し、不明・複数の日付があり判別できない場合は「不明」とします。システムプロンプトは含めず、Ollamaへの送信・会話の開始・記事Mapへの保存は行いません。投稿日はコピー用であり、LLM送信項目は変更しません。

表示は短い `[&記事タイトル]について要約して` とし、Ollamaへは実際のタイトル・著者・本文と依頼文を送ります。タイトルボタンから要約・感想・修正点・引用列挙を選べます。要約・感想・修正点・引用列挙は、専用の固定systemと今回の依頼・対象記事1件で独立した会話区間を開始します。自由入力では、全画面で共有する最新区間の完了済みの依頼・AI回答も送信します。他の記事・区間は送りません。同名の記事も記事IDで区別し、過去の記事へ戻って保持済み本文を使えます。普通に入力した文章やAIの `[&...]` は記事ボタンになりません。コピーは画面の依頼文を対象とします。

記事本文は記事Mapに、画面用の依頼文・回答・記事参照は記事タブの表示履歴に保持し、LLM送信本文を履歴へ複製しません。旧版の送信本文複製は読込時に削除し、記事Mapと表示履歴を維持します。記事本文・履歴・会話区間は拡張専用のIndexedDBへ保存し、ブラウザ終了・拡張再読込後も復元します。他の2タブのstorage.localによる保存は維持します。記事タブの「新しい会話」と接続先変更で記事本文・履歴・区間・未処理依頼をまとめて削除します。未処理依頼はブラウザセッションに束縛し、再起動後は無効にします。生成途中の回答は中断表示で復元し、自動で再送しません。記事情報は設定JSONへ含めません。受け渡し用の識別子は送信開始の保存と同時に一度だけ消費し、再読込で同じ要約を再送しません。接続待ちの依頼を編集すると自動送信を取り消します。

記事ページからの要約依頼は全ホーム共通の待機キューへ受付順に追加し、1件ずつ実行します。同じ記事の要約が実行中・待機中なら追加分を無視し、既存依頼と本文を保持します。完了・失敗・中止後は再要約できます。失敗した依頼だけを飛ばして次へ進み、「中止」は実行中と待機中をすべてキャンセルします。待機件数は記事チャットに表示します。未接続なら「LLMの設定」で接続・モデル選択後に送信します。自動進行には接続済みの「記事について」画面を開いておく必要があります。ブラウザ再起動後は待機分を自動再送しません。詳しくは[要約キュー仕様](spec/ARTICLE_SUMMARY_QUEUE_SPEC_0.1.1.md)を参照してください。全タブ共通のモデルを使い、通常用プロンプトや登録済みタグは記事の専用プロンプトに混ぜません。

自由入力の対象区間は履歴とともに全ホーム画面で共有し、新しい記事操作の送信開始時に更新します。入力中に別画面から対象が変わった場合は、現在の対象への送信を確認します。取消では下書きを保持し、送信しません。背景処理でも表示時点の区間と共有区間を照合し、送信直前の変更は自動再送せず拒否します。区間が未選択・無効なら送信を止めます。チャット欄には説明・現在対象・記事一覧を常設せず、△▽で過去の発言へ戻り、その記事タイトルから要約・感想・修正点・引用列挙を選び直して自由入力を続けます。容量整理で表示履歴から外れた記事を再操作する場合は記事ページから取り込み直します。履歴から区間の開始発言が消えても、区間ID・記事ID・開始操作を保持します。本文は毎回Mapから一度だけ付与します。

記事と依頼文の合計は200,000文字まで、記事の保存データ全体は8MiBまでです。容量超過では記事を黙って削除せず取り込み・送信を止めます。記事タブではOllamaの自動切り捨てを禁止し、モデルのコンテキストに収まらない場合はエラーにします。必要ならOllama側のコンテキスト設定を調整してください。[Ollamaのコンテキスト設定](https://docs.ollama.com/context-length)。

Firefoxでは「記事について」からの接続時に、会話送信の同意に加えてWebサイト内容の送信同意（`websiteContent`）を求めます。拒否しても通常の会話・タグ提案・note閲覧は利用できます。[Firefoxの送信同意](https://extensionworkshop.com/documentation/develop/firefox-builtin-data-consent/)。

仕様原文は [記事チャット追加仕様](spec/ARTICLE_CHAT_SPEC_0.1.0.md)、保存方式などの実装詳細は [基本設計書](spec/OshaberiNote_SPEC_0.1.0.md) に記録しています。

記事タイトルのダイアログから「この記事を開く」で元記事を別タブに開けます。本文中の文字列リンク・添付ファイルのURLとリンクカードのタイトル・著者・URLを取り込み、未取得のカード情報は未取得と明記します。リンク先の記事本文やファイル本体は取得しません。引用列挙では参照URL一覧を送信時に添えます。設定したnoteユーザーIDと記事の作者IDが一致すると、本人の作品であることを送信時に伝えます。完了したAI回答のHTTP(S) URLやMarkdownリンクは別タブで開けます。AIの説明・引用判定・著者推定の正確性は保証しません。

noteのクリエーターページへリンクするカードは「種類：クリエーターページ」と区別し、カードに表示されたタイトル・取得できる紹介文・URLを取り込みます。記事の著者欄は付けません。紹介文はカード内の情報だけを使い、プロフィールページを追加取得しません。

外部サイトのリンクカードはタイトル・URLを取り込み、「著者未取得」の行は付けません。noteの記事カードでは、取得できる著者名または「著者未取得」を表示します。

GitHubリポジトリの埋め込みは、記事側の枠にある元URLを本文へ含めます。Iframelyのiframe内部は取得しません。

その他の埋め込みと古い形式のカードも、記事側の元URLを優先して取得します。元URLがなければiframe要素の`src`・`data-src`を読み、確認済みのYouTube・Spotify・CodePen形式だけ通常URLへ変換します。変換できない表示用URLは「埋め込みURL：…」と区別し、どのURLも確認できなければ「URL：（未取得）」としてカードの存在を残します。スクロール・iframe属性の書き換え・追加通信による強制読み込みはしません。従来の表示中テキストやキャプションは維持します。今回のURL補完ではiframe内部を読みません（既存の、読み込み済みnote記事カードからタイトル・著者を取得する処理は維持します）。

既知の添付ファイル枠は「[ファイルダウンロード]」「ファイル名：…（表示サイズ）」「リンク先URL：…」へ整形し、ダウンロード操作用の文言を省きます。ファイル本体は取得しません。

## 設定移行

ひきこもりnote形式1～7とおしゃべりnote形式1を読み込みます。存在する共通項目だけを検証・適用し、欠けた項目は現在値を維持します。未対応項目は破棄し、不正な対応項目があれば全体を適用しません。`false` や空の値も有効な設定値として扱います。

出力は `oshaberi-note-settings` 形式1で、会話や接続許可状態は含めません。ひきこもりnoteへの読み戻しは、そちらの別途改修が必要です。今回ひきこもりnoteは変更していません。

## 検証範囲

自動試験は既存のnote表示・保存・お気に入り処理に加え、会話の競合、初期化後の遅延応答拒否、設定移行、ストリーム分割と異常応答を確認します。元製品専用の3モード切替と旧JSON全置換の試験は、本製品の固定モード・部分移行の試験へ置き換えています。

実ブラウザの権限ダイアログ・noteの最新DOM・LAN接続・実モデル生成は別途手動確認が必要です。手順は [手動確認](docs/manual-test.md) に記載しています。

記事本文はIndexedDBの記事ID別レコードに一度だけ保存し、履歴・区間・受け渡し情報と同一トランザクションで更新します。本文が変わらない回答更新では本文レコードを書き直しません。旧セッションが残っていれば永続DBへ移行しますが、旧版の終了・再読込ですでに消えたデータは復元できません。記事は設定JSONの移行対象外です。拡張の削除やブラウザによる保存データ削除では失われるため、バックアップ機能の代わりにはなりません。0.1.1では同じ著者の他記事要約を感想とその続きの参考情報へ添える、簡易的な連作対応を試作しています。連作専用タブや複数記事本文の一括送信はありません。
