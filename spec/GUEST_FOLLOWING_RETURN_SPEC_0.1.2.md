# おしゃべりnote 0.1.2 未ログイン時のTL帰還リンク

移植元：HikikomoriNoteタグ0.3.2（e6f55485de8e28455aaddcacea85021a2d87014a）のsrc/note-ui.js、src/content.js、およびspec/hikikomori-note_SPEC_v0.3.2.md。移植元は変更しない。今回は開発用の変更のみとし、コミット・公開・リリースは行わない。

## 対象と動作

note公式ページ上におしゃべりnoteが追加する「フォロー中のTL」を共通対象とする。共通左メニュー・共通ハンバーガー・作者ページ・記事の固定欄／ハンバーガー・プレビュー・質問箱・メンバーシップ・マガジンのTLリンクへ適用する。

現在の公式ヘッダで未ログインを確認できた場合だけ、リンク先を次へ変更する。

https://note.com/search?q=&context=note&mode=search&sort=new

名称は「フォロー中のTL」を維持し、titleを「未ログインのため検索画面を開きます」とする。ログイン済み・判定不能・ヘッダ未表示では従来のhttps://note.com/followingへ戻し、追加したtitleも外す。公式リンクそのものと、専用ホーム・設定画面のTLリンクは変更しない。

## 判定条件

可視の公式navbarヘッダにある同じnav[aria-label="アカウント"]で、note.com/loginへの「ログイン」とnote.com/signupへの「会員登録」が両方可視であることを要求する。同時に可視の公式nav[aria-label="自分のコンテンツや通知"]がある場合は未ログインと判定しない。

本文・拡張所有DOM・外部URL・認証情報付きURL・非表示要素・片側だけの表示・異なるアカウントnavの組み合わせは採用しない。Cookie・認証情報を参照せず、利用者IDも自動取得しない。

## 再確認と操作

既存DOM変更通知のinvalidatePaidCardsで再確認フラグを立て、次の同期で更新する。変更のない定期同期では再走査しない。リンク作成時、URL変更、ON/OFF変更と、pointerdown・mousedown・focus・contextmenu・click・auxclickの操作直前にも現在のDOMを確認する。新しいタイマー・Observerは追加せず、既存Observerの属性対象にaria-hiddenとdata-header-stateを追加する。

保持するのはリンクとイベント解除用関数の対応、再確認フラグのみで、ログイン判定結果を共有変数・設定・storageへ保存しない。別ブラウザタブのログイン・ログアウトを独自に追跡しない。クリックの既定動作を取り消さず、通常・修飾クリック・中クリック・右クリックから開く動作を維持する。OFF・停止・不要となったリンクでは専用のイベントを解除し、遷移先を元へ戻す。

## 検証

遅延ヘッダ、DOM差し替え、判定不能・矛盾、本文・外部・不可視・片側の偽陽性防止、各追加TL導線、操作直前の更新、再確認回数、OFF・停止を自動試験する。既存のDOM通知が追加属性を拾うことも確認する。実ブラウザ・実際の未ログイン遷移の未確認項目は分けて報告する。新設定・権限・通信・拡張間連携は追加しない。
