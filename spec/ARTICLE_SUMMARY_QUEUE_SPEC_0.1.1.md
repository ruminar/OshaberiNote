# 記事要約の待機キュー（0.1.1）

記事ページの「この記事を要約」で取り込んだ依頼は、全ホーム画面で共有するFIFOキューに追加する。他の生成が実行中でも取り込みを受け付け、同時生成は従来どおり全チャットで1件に制限する。

取り込み元と同じウィンドウの右隣が、この拡張自身のhome.htmlなら再利用する。既存画面へ通知し、左メニューの「おしゃべり」と上部の「記事について」を選択する。URL変更・再読込・ブラウザタブのアクティブ化は行わない。その画面が生成中の場合は完了まで切り替えを待ち、生成を中断しない。通知の受領を確認できない場合、または右隣が別ページの場合だけ、右隣にactive:falseで新しいホームを開く。

同じ記事IDの要約が待機中または実行中の場合、新しい依頼を追加しない。既存の依頼を残し、記事Mapも上書きしない。完了・失敗・中止後の再要約は許可する。判定と受付は背景処理の同じ直列キュー内で行う。

- 受付順に1件ずつ送信する。複数ホームから同じ依頼を送信しようとしても、背景処理が一度だけ受け付ける。
- 失敗した依頼は自動再送せず、その依頼だけを飛ばして次へ進む。処理結果や保存結果を確認できない場合は、安全のため自動進行を止める。
- 利用者の「中止」は、実行中の生成と待機中の要約すべてをキャンセルする。待機だけの状態でも中止できる。
- 待機件数を記事チャットに表示する。待機依頼の実行で自由入力の下書きを送信・上書きしない。
- 記事ページの左メニューは、操作ボタン下の通知文のために最大高さ288pxを確保する。下のプロフィール欄も60px下げ、通知文と重ならないようにする。
- 実行時に受付時の記事本文の指紋を照合する。同じ記事が別の内容で取り込み直された場合、古い依頼へ新しい本文を流用せず、その依頼を拒否する。
- 各要約は対象記事1件で新しい会話区間を開始する。要約Mapへの登録は正常完了した回答だけを対象とする。

待機依頼は既存の記事セッションのrequestsを再利用し、記事ID・操作・会話epoch・本文の指紋だけを保持する。記事本文の複製は保持しない。既存の待機件数上限64件と記事保存全体8MiBの制限を維持する。

自動進行には、接続済みのホーム画面が必要。別の会話タブやお気に入り・設定メニューの表示中も継続し、表示や下書きを変更しない。受付元のホームに限定しない。ホームをすべて閉じた場合は、同じブラウザセッション内で再び開いて接続すると残りを進められる。ブラウザ再起動後は待機依頼を無効にし、自動再送しない。生成中の回答は中断扱いとする。

記事タブの「新しい会話」・接続先変更では既存仕様どおり待機依頼も削除する。拡張OFF・モデル変更・設定取り込みでも待機を取り消し、別の設定で意図せず再開しない。

通常会話・タグ提案・記事タイトルの操作メニューを新しいキューへ統合する変更は含めない。
