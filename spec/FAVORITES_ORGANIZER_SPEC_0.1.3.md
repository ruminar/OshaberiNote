# お気に入り整理画面（0.1.3）

設定内のお気に入り画面を、登録済み項目のグループ間整理に集中したUIへ変更する。Shiftキーによる登録機能、一括移動、新たな登録対象は今回実装しない。既存の保存キュー・項目検証・4／8グループ制限・JSON形式は維持する。コミット・公開は行わない。

- タグ手入力の追加フォームを撤去する。noteページやAI回答からの登録機能は維持し、空一覧ではそれらの導線を案内する。
- グループ選択と名前変更の下に、共通の「移動先」を1つ置く。初回は未選択とし、選択した宛先は画面を開いている間だけ保持する。設定やJSONへ保存しない。
- 操作元自身と非表示グループを宛先から除く。グループ切替や通常／2段変更で宛先が無効になった場合は未選択へ戻す。別の宛先へ自動変更しない。
- 各行は項目リンク・↑・↓・削除・移動とする。移動は塗りボタン、削除との間に少し広めの余白を置く。長いタイトルでも操作部を揃え、狭幅では項目リンクと操作部を上下に分ける。
- 移動先は一覧スクロール領域の外に置く。一覧は画面高に応じて残りの高さを使い、短い画面でも操作可能な最小高を確保する。独自のstickyや新しい監視・タイマーは追加しない。
- 移動・削除・並べ替え・外部同期の再描画時も、グループ別のスクロール位置を保持する。末尾の項目が減って保存位置を維持できない場合はブラウザの最大値まで補正する。
- 宛先未選択・保存中・結果未確認・破損時は移動を無効にする。移動の成功は一覧近くのrole=statusへ「項目を宛先へ移動しました」と具体的に表示する。失敗時は削除や成功扱いにせず、既存の競合・再確認処理を使う。
- お気に入り操作の保存中・成功通知は右側の一覧近くだけに表示し、左メニューの状態文を更新しない。二重表示と左メニューの位置変動を防ぐ。エラーや再確認が必要な場合の既存案内、設定保存・インポート等の案内は維持する。
- キーボードで実行した操作後は、残った同じ項目または隣の項目の対応ボタンへフォーカスを戻す。スクロールを強制しない。項目がなくなったら一覧領域へ戻す。

移動先の維持・無効化、連続移動、全5種類の項目、保存失敗・競合、スクロール・フォーカス、上下／ドラッグ並べ替え、狭幅・空一覧を検証する。旧手入力フォームを前提とするテストは整理操作の検証へ更新する。

## 検証結果（2026-11-16）

- 構文・自動テスト581件成功。新規5件と既存UI試験の更新により、全5種類の連続移動、宛先保持・無効化、一覧位置・フォーカス、保存失敗・重複、破損・結果未確認、上下／ドラッグ操作を確認した。
- ローカルChromeで実際のhome.js・routing.jsとCSSを使い、70項目のサンプルを表示した。PC（内部幅1264px）と狭幅（504px）で横はみ出しなし、一覧スクロールと宛先の分離、移動後の位置保持・フィードバックを確認した。PCの操作列の整列と狭幅の上下配置もスクリーンショットで確認した。狭幅のパネル撮影では確認用HTMLのサイドメニューを省略している。
- Chromium／Firefoxの0.1.3開発版を再生成・照合した。0.1.2のタグ・提出ZIPは保持する。
- 実ブラウザへインストールした状態の操作、Firefox／Edge、スマートフォン実機・500px未満の表示は未確認。新規設定・保存形式変更・Shift登録・一括移動は追加していない。コミット・push・公開は行っていない。
