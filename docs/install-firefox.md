# Firefox 手動インストール

PC版Firefox 140以上で、既存のひきこもりnoteを無効にしてください。`about:debugging#/runtime/this-firefox` →「一時的なアドオンを読み込む」から、このフォルダの `manifest.json` を指定します。Androidは対象外です。

Ollamaを起動し、拡張アイコン →「LLMの設定」→「接続・再試行」→ 接続権限と会話送信の任意同意（personalCommunications）の許可 → モデル選択 →「おしゃべり」→ 送信の順で確認します。拒否しても既存のnote機能は利用できます。「LLMの設定」で接続先を変更すると会話・モデル選択・システムプロンプトを初期化します。

必要な場合はOllamaの `OLLAMA_ORIGINS` にこの専用ホームの実際の `moz-extension://実行時UUID` を追加して再起動します。アドオンIDと実行時UUIDは異なります。全サイト・全拡張を許可しないでください。

ローカル専用運用ではOllama側で `OLLAMA_NO_CLOUD=1` を設定して再起動してください。HTTPのLAN通信は暗号化されません。このZIPは未署名の手動読み込み用です。一時的なアドオンはFirefoxの再起動で外れるため、継続利用には別途署名済みパッケージが必要です。

記事送信でコンテキスト上限のエラーが出る場合、短い質問でも記事本文を含めるため、Ollamaのコンテキスト長を増やすか短い記事で試してください。20万文字の入力上限とモデルのトークン上限は別です。Ollamaアプリの設定、または起動するPowerShellで `$env:OLLAMA_CONTEXT_LENGTH = '16384'` を設定してから `ollama serve` を実行します。既に動作中のOllamaは先に終了し、既存の `OLLAMA_ORIGINS` 設定も維持してください。必要な値は記事・モデルによって異なり、拡大するとメモリ使用量が増えます。`ollama ps` のCONTEXT欄で実際の割当を確認できます。アドオンは本文を自動で切り捨てず、自動再送もしません。

設定から「システム・ダーク・ライト」を選べます。「システム」はOS・ブラウザの配色設定に追従します。チャットはCtrl+Enterで送信、Enterで改行します。IME変換中は送信しません。

通常チャット用のシステムプロンプトも「LLMの設定」で保存できます。変更の保存時は通常タブの会話だけを初期化し、空欄で保存すると追加のプロンプトを解除します。

入力は最大200,000文字です。通常会話・タグ提案の履歴は直近10往復・最大2MiBを保持し、古い分から自動整理するため、履歴量で会話を打ち切りません。長文はOllama側でも切り捨てられる場合があります。

「おしゃべり」上部の「通常の会話」「タグの提案」をタブとして切り替えます。初回は通常タブで、以後は最後に選んだ会話タブとその履歴を開き直し時に復元します。復元だけでは質問を再送しません。各タブの履歴は別々に保存します。タグタブの初回選択時だけ最初の質問を作り、接続・モデル選択済みなら送信します。未接続なら入力欄で待ち、再選択では再送しません。専用プロンプトv1.2と全4グループの最新登録タグ名はタグタブの送信だけに付与します。「新しい会話」は選択中のタブだけ初期化します。提案タグの登録は利用者の操作時だけ行います。

記事ページ（PC幅1100px以上）の左メニューから「この記事を要約」を押すと、新しいブラウザタブで「記事について」を開き、既存履歴へ要約を追加します。記事タイトルボタンから元記事を別タブで開いたり、感想・修正点・引用の列挙を依頼できます。記事本文と記事会話はこのブラウザのIndexedDBへ保存し、終了・再起動後も復元します。記事タブの「新しい会話」で本文・履歴を削除し、他の2タブは維持します。再起動後に未処理依頼を自動送信しません。記事は自動で切り捨てず、モデルに収まらなければエラーになります。
記事についての接続時は「Webサイトの内容」の送信同意も必要です。通常の会話・タグ提案には追加の同意は不要です。

「記事について」の要約・感想・修正点・引用列挙は、対象記事1件と今回の依頼で新しい会話区間を開始します。自由入力だけは同じ区間の完了済みの依頼・回答を含めます。他の記事や区間は送りません。通常会話・タグ提案は従来どおり履歴を利用します。

「記事について」の自由入力は、全ホーム画面で共有する最新の会話区間の依頼・回答を付けて送ります。他のホーム画面で新しい記事操作を送信すると対象も切り替わります。入力中に対象が変わった場合は、現在対象への送信を確認します。取消では下書きを保持します。△▽で過去の発言へ戻り、その記事タイトルから操作を選び直して、続けて自由入力できます。容量整理で表示履歴から外れた記事を再操作する場合は記事ページから取り込み直します。

「記事について」の履歴は往復数で制限しません。履歴最大2MiB・本文を含む保存全体最大8MiBの容量上限は維持し、容量を超えた履歴は古い往復から整理します。通常会話・タグ提案は従来どおり直近10往復です。

0.1.1試作では、新しく完了した要約を著者ID・記事ID別に保存し、感想とその続きに同じ著者の他記事要約を参考として送信します。0.1.0の過去回答は自動登録しないため、記事を再要約してから試してください。連作であるとは断定させず、要約・修正点・引用列挙には他記事要約を付けません。ブラウザ終了後も要約は残りますが、記事タブの新しい会話と接続先変更では本文・会話と一緒に削除します。既存の8MiB保存上限と送信上限は維持します。
