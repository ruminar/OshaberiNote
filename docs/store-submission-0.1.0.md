noteのホームをOllamaとのチャット画面に置き換える非公式拡張です。タグ提案、記事の要約・感想・引用元の列挙、お気に入り管理に対応。Ollamaとモデルの用意が別途必要です。

### 2.3 詳細説明：3ストア共通

以下のブロックを、Chrome・Edgeの詳細説明、Firefoxの説明欄へ転記します。

```text
おしゃべりnoteは、noteの記事を見つけ、読み、内容についてOllamaと話すための非公式ブラウザ拡張です。ひきこもりnoteの便利な機能はそのままに、noteの通常ホームを、チャットとお気に入りを使える専用ホームに置き換えます。

【できること】
・通常の会話、タグの提案、記事についての3つのチャットを切り替えられます。
・登録済みのお気に入りタグを参考に、新しいタグの候補を相談できます。
・AIが提案したタグからnoteを検索したり、4つのお気に入りグループへ登録したりできます。自動登録はしません。
・記事ページの「この記事を要約」から、閲覧できる記事のタイトル・著者・本文を取り込めます。
・取り込んだ記事について、要約・感想・修正点・引用や参照元の列挙を依頼できます。
・記事タイトルの操作メニューから、元の記事を新しいタブで開けます。
・本文中のリンクURL、添付ファイルのリンク、リンクカードの取得できるタイトル・著者・URLも扱います。リンク先の記事本文やファイル本体は取得しません。
・お気に入りのタグ・作者・マガジン・メンバーシップ、作者の表示管理、noteの表示設定を管理できます。
・システム・ダーク・ライトのテーマ、Ctrl+Enter送信、メッセージコピー、発言単位の移動、太字・箇条書き・URLリンク表示に対応します。

【利用に必要なもの】
Ollama本体と対応モデルを別途用意してください。初期接続先は、このPC上で起動したOllamaです。「LLMの設定」で接続先を確認し、接続権限を許可してモデルを選択します。Ollama未接続でも、お気に入り・設定・通常のnote閲覧は利用できます。

【送信する情報】
利用者が入力したメッセージ、会話に必要な履歴、システムプロンプトを、利用者が設定したOllamaへ送ります。タグ提案では登録済みタグ名も送ります。記事についての依頼では、利用者が明示的に取り込んだ記事情報を送ります。
要約・感想・修正点・引用列挙は対象記事1件で開始します。その後の自由入力には同じ会話区間の依頼と回答を含め、他の記事や区間の履歴は送りません。
記事を閲覧するだけで本文をOllamaへ送ることはありません。Cookieや認証情報を収集してOllamaへ送ることもありません。開発者のサーバーやアクセス解析サービスへの送信はありません。クラウドモデルを選んだ場合は、Ollama側から外部へ通信します。

【保存と削除】
設定と会話、取り込んだ記事はブラウザ内に保存し、ブラウザ終了後も復元します。「新しい会話」で選択中の会話を削除でき、記事タブでは保存した記事本文も削除します。会話・記事は暗号化していません。設定JSONの書き出しに会話や記事本文は含みません。

【ご利用前に】
AIの回答や引用元の判定は、使用するモデルによって異なり、正確性を保証しません。未読み込みのリンクカードは、タイトルや著者を取得できない場合があります。長い記事がモデルのコンテキストに収まらない場合はエラーになります。
noteのダッシュボードや一部のおすすめ・有料記事カードなどを非表示にする設定もあります。拡張OFFではnote本来の表示へ戻せます。ブラウザ自体の新しいタブページや起動時ホームページを変更する拡張ではありません。
PC版ブラウザ向けです。ひきこもりnoteとの同時有効化は避けてください。note株式会社・Ollamaとは関係ありません。
```

説明には、追加ソフトが必要なこと、note内のホーム転送と表示変更、Ollamaへの送信を含めています。Mozillaも、機能と送信情報が掲載説明から分かることを求めています。[Mozilla Add-on Policies](https://extensionworkshop.com/documentation/publish/add-on-policies/)

## 4. 権限を使う理由：Chrome・Edge共通原稿

申請画面に表示された権限ごとの欄へ、該当する文章を転記します。宣言していない `history`・`tabs`・`cookies`・`nativeMessaging`・`clipboardRead` などを、使用する権限として追加しないでください。

### storage

```text
拡張のON/OFF、noteの表示設定、noteユーザー名、お気に入り、作者の表示管理、テーマ、Ollama接続設定と会話履歴をブラウザ内へ保存し、開き直した際に復元するために使用します。記事本文と記事会話は拡張専用IndexedDBに保存します。保存データを開発者のサーバーへ送信する用途には使用しません。
```

### declarativeNetRequestWithHostAccess

```text
拡張ON時にnoteの通常ホームを拡張内の専用ホームへ転送するために使用します。通常ホームの先行取得を遮断し、ダッシュボード無効化が有効な場合はダッシュボードへのアクセスも専用ホームへ転送します。ルールの対象はnote.comのホームと対象ダッシュボードに限定し、他サイトの通信を監視・変更する用途には使用しません。拡張OFFではこれらのルールを解除します。
```

### https://note.com/*

```text
note内のホーム転送、ヘッダーから専用ホームを開く操作、お気に入りと作者の表示管理、設定に応じたカード等の非表示、記事の取り込みボタンの配置に必要です。記事の取り込みは利用者がボタンを押した場合だけ行い、本文・URL・記事IDの対応を確認します。note埋め込みカードの読み込み済み情報も対象記事の参照情報として扱います。Cookieや認証情報を取得して送信する用途には使用しません。
```

### 任意ホスト権限：HTTP・HTTPS

```text
利用者が指定するOllamaサーバーへ接続するため、HTTPとHTTPSの接続先を任意権限として宣言しています。接続先はlocalhostに限らず、利用者が管理するLAN内やHTTPSのサーバーに変更できます。全ホストへのアクセスを自動取得せず、「接続・再試行」を押した時に設定先ホストだけを要求します。実際のAPI通信は保存済みの接続先URLのモデル一覧と会話送信に限定し、Cookie等の資格情報を付けず、リダイレクトにも追従しません。任意のウェブサイトへスクリプトを注入するための権限ではありません。
```

HTTPとHTTPSで欄が分かれている場合は、上の同じ文章を使えます。任意権限の広い宣言と、実際の要求先・通信先の制限を区別して説明します。

## 5. リモートコード

選択：**使用していない／No**。

説明欄がある場合：

```text
拡張の実行に使用するJavaScript・CSS・HTMLはパッケージ内に同梱しています。Ollamaから受け取る応答はJSONと文章データとして処理し、JavaScriptとして実行しません。AIのツール実行要求にも対応していません。回答中の太字・箇条書き・リンク・タグ操作は同梱コードが安全なDOM生成で表示します。外部からコードを取得してevalや動的スクリプトとして実行する処理はありません。
```

LLMとのAPI通信は、リモートの応答文を実行することとは異なります。Edgeの申請でもリモートコードの使用有無を回答します。[Microsoft公式のプライバシー記入手順](https://learn.microsoft.com/en-us/microsoft-edge/extensions/publish/publish-extension#step-6-enter-privacy-information)

## 6. データ利用の申告：Chrome・Edge

### 6.1 データ区分の回答案

「開発者が受け取らない」ことを理由に、全項目を「収集なし」とはしません。ローカルで扱うデータも申告対象になるというChromeの説明に基づく整理です。[Chrome公式User Data FAQ](https://developer.chrome.com/docs/webstore/program-policies/user-data-faq#3_does_an_extension_need_to_disclose_user_data_handling_if_the_data_is_only_processed_or_stored_locally_on_a_users_device)

| 画面のデータ区分 | 回答案 | 実装上の根拠 |
| --- | --- | --- |
| 個人を特定できる情報 | 該当を選択 | 設定する公開noteユーザー名、作者の表示名・ユーザーID、お気に入りの作者情報をローカルに扱う。取り込んだ記事やカードの著者名はOllamaへ送る |
| 個人的なコミュニケーション | 該当を選択 | 入力メッセージ、システムプロンプト、会話履歴、AIの回答を保存・処理し、必要な内容を設定先Ollamaへ送る |
| ウェブ履歴 | 該当を選択 | note内の現在ページを判定し、明示的に取り込んだ記事のURL・タイトル等を保存する。全ブラウザの履歴一覧を取得するという意味ではない |
| ウェブサイトのコンテンツ | 該当を選択 | 明示的に取り込んだ記事本文・タイトル・著者、リンク、カード情報を保存・送信する |
| ユーザーのアクティビティ | 操作ログ・行動分析の区分としては選択しない | キー入力・クリック・スクロールを操作の実行に使うが、行動ログとして蓄積・分析・送信しない。会話入力の取り扱いは上のコミュニケーションで申告する |
| 認証情報 | 専用の収集対象としては選択しない | パスワード・Cookie・認証トークンを取得して送信しない。公開ユーザー名をパスワード等と混同しない |
| 健康情報 | 専用の収集対象としては選択しない | 健康状態を取得する機能や専用フォームはない |
| 財務情報・支払い情報 | 専用の収集対象としては選択しない | 決済・支払い履歴・カード情報を取得する機能はない |
| 位置情報 | 選択しない | 位置情報APIやIPによる位置推定を行わない |

この表は0.1.0の機能に対する回答案です。任意の会話・記事本文に個人情報や機微な内容が書かれていれば、それらも利用者の送信内容に含まれ得ます。「そのような文字列を送信できない」とは説明しません。画面側の区分定義が違う場合は、上の実際の取り扱いと照合してください。

### 6.2 利用方法の説明欄

```text
データは、note閲覧の設定・お気に入り管理・Ollamaとの会話・記事への依頼という、利用者に提供する機能のために扱います。設定と履歴はブラウザ内に保存します。利用者が接続を許可したOllamaへ、入力メッセージ、必要な会話履歴、システムプロンプトを送信します。タグ提案では登録済みタグ名、記事への依頼では明示的に取り込んだ記事情報も送信します。開発者のサーバー・アクセス解析・広告サービスへ送信せず、販売や広告目的での共有も行いません。クラウドモデルの利用時はOllama側から外部へ通信します。
```

### 6.3 データ利用に関する確約

現行の実装に対する回答として、次の趣旨の確認欄は選択できます。管理画面に表示される原文も確認してください。

- データを販売せず、承認された目的外で第三者へ移転しない。
- 拡張の説明した機能と無関係な目的でデータを利用・移転しない。
- 信用評価や貸付の判断目的で利用・移転しない。

「Ollamaへの送信はない」「すべての通信を暗号化している」「すべての保存データを暗号化している」といった確約は、0.1.0では行えません。既定のローカル接続とLANのHTTP接続、暗号化していないブラウザ保存領域の実装を、そのまま説明してください。

## 8. 審査担当者向けメモ

Chromeのテスト手順欄、Edgeの審査メモ、FirefoxのNotes for Reviewers等に使用します。欄が短い場合は後述の短縮版を使います。

### 8.1 詳細版

```text
この拡張は、利用者が管理するOllamaサーバーに接続するnote閲覧支援ツールです。拡張自体のアカウント登録・ライセンス購入・APIキーは不要です。接続先Ollamaとローカルチャットモデルを別途用意してください。開発者のサーバーにログインする仕組みはありません。

1. Ollamaにチャットモデルを登録して起動してください。初期接続先は、このPC上で起動したOllama（標準ポート11434）です。
2. 拡張アイコンから専用ホームを開きます。UIは日本語です。noteの通常ホームを開いた場合も、拡張ON時は専用ホームへ移動します。ブラウザの新しいタブや起動時ホームページの設定を変更するものではありません。
3. 「LLMの設定」を開き、接続先を確認します。Ollamaの起動手順を開くと、現在の拡張Originを許可するWindows用コマンドが表示されます。必要に応じてOllama側のOrigin許可を設定してください。全サイトや全拡張の一括許可は不要です。
4. 「接続・再試行」を押し、設定先ホストへのアクセスを許可します。Firefoxでは会話送信への任意同意も許可してください。モデル一覧から登録したモデルを選びます。
5. 「おしゃべり」の「通常の会話」で入力し、送信またはCtrl+Enterで送ります。「タグの提案」は最新のお気に入りタグを参考情報に使います。提案されたタグの登録は、利用者の操作時だけ行います。
6. 幅1100px以上のPC画面で、無料で読めるnote記事を開いてください。既知の記事構造と左側の余白を確認できる場合、左メニューに「この記事を要約」が表示されます。押すと記事を取り込み、新しいブラウザタブの「記事について」に依頼を追加します。記事を開いただけではOllamaへ送りません。
7. Firefoxの記事送信では、Webサイト内容を送信する任意同意も必要です。「記事について」で「LLMの設定」から接続を許可してください。拒否中は記事送信を止め、他の機能は利用できます。
8. 記事の依頼文にある[&記事タイトル]を押すと、「この記事を開く」「要約」「感想」「修正点」「引用を列挙」の操作メニューを開けます。自由入力だけは同じ記事の会話区間の履歴を使います。
9. 「設定」でテーマやnoteの表示を変更できます。ダッシュボードや一部カードを隠す設定が含まれます。拡張OFFではnote本来の動作に戻ります。既存のひきこもりnoteは無効にして試してください。

モデル一覧を取得できても会話POSTのOriginが許可されていないと403になる場合があります。記事がモデルの枠に収まらない場合はエラーにし、自動再送しません。長文記事を試す場合はOllama側のコンテキストを調整してください。Windows用の起動手順には16,384トークンの設定例があります。

実行コードは同梱しており、Ollamaの応答をコードとして実行しません。ビルド工程はファイルのコピーとFirefox向けManifestの生成だけで、JavaScriptの圧縮・難読化・トランスパイルは行っていません。ソースのルートでNode.jsから node scripts/package.mjs firefox を実行すると、追加のnpm依存なしでFirefox用フォルダを生成できます。ソースは https://github.com/ruminar/OshaberiNote/tree/0.1.0 で公開しています。

自動試験470件に加え、Chrome・Edgeで主要操作、ローカルgemma3:12bで記事の参照URL列挙を確認しています。Firefoxの実ブラウザ操作を確認済みとするものではありません。AI回答の正確性はモデルによります。
```

#### Firefoxのデータ送信申告

現行Manifestは次の宣言です。**`required: none` は、任意の送信も一切ないという意味ではありません。**

```json
{
  "required": ["none"],
  "optional": ["personalCommunications", "websiteContent"]
}
```

```text
必須のデータ送信はありません。会話送信はpersonalCommunications、記事の送信は追加でwebsiteContentの任意同意を要求します。利用者が接続を許可したOllamaへ、会話と明示的に取り込んだ記事の情報を送信します。同意がない場合は該当する送信を止め、既存のお気に入り・設定・note閲覧は利用できます。開発者のサーバーやアクセス解析へは送信しません。
```

送信・収集を行うかと全体で聞かれた場合、単に「なし」と回答する原稿ではありません。Firefoxの送信同意とChromeのデータ取り扱い申告は、対象とする範囲や分類が同一ではないため、6のチェック表をそのままManifestへ置き換えません。[Mozilla公式の組み込み同意仕様](https://extensionworkshop.com/documentation/develop/firefox-builtin-data-consent/)
