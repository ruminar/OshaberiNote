# お気に入り8グループ実装報告（0.1.2）

## 実装内容

- 設定に「お気に入りグループの表示」を追加。初期値は通常（1段・4グループ）、2段（8グループ）へ切替可能。
- サイドバーは4列、ハンバーガー内は8個時に8列。配置先の親コンポーネントで判定する。
- 管理画面、記事／作者／マガジン／メンバーシップ登録、タグ追加、AI回答のタグ登録、移動先を同じ操作可能グループ処理へ集約。
- 通常表示に戻しても⑤〜⑧の名前・登録内容・順序を維持する。選択が後半なら①へ補正し、選択更新番号を進める。
- バックグラウンドの保存キュー内で最新設定を検証し、非表示グループへの追加・削除・移動・並べ替え・名前変更・選択を拒否する。記事の重複防止は非表示グループも対象。
- 表示設定の変更だけではLLMの会話を初期化しない。登録済みタグを参照する既存のタグ提案は保存済み全グループからタグだけを抽出する。

## 保存形式とJSON

[確定仕様・JSONサンプル](../spec/FAVORITE_GROUPS_EIGHT_SPEC_0.1.2.md)に8グループと5種類の項目を記載した。

内部保存は既存キー `oshaberiNote.settings.v2`、`{id,name,tags}` を維持する。初期・旧保存は4グループのまま読み、初めて2段を保存すると不足分を補って8グループ・tagSchemaVersion=7へ移行する。以後は通常表示でも8グループを保存する。旧2〜6の読み込みと破損保護は維持する。

外部JSONは `format:oshaberi-note-settings`・`schemaVersion:1` を維持する。表示値 `settings.favoriteGroupDisplay` はnormal／double。グループは `settings.tagGroups` の `{id,name,items}` で、group1〜group8のID順に書き出す。これはひきこもりnoteの8グループ形式と共通で、製品の表示モードには依存しない。

ひきこもりnote JSON1〜9を読み込める。旧4グループJSONを既存8グループへ読み込む場合も後半を維持する。省略グループは現在値を維持し、空itemsは明示的クリア。入力順には依存せず、重複ID・不正な対応項目は従来方針どおり全体を拒否する。未知形式・将来版の外枠を無条件で許可する変更は行っていない。

ひきこもりnoteのnormal-double／normalは表示値へ対応付ける。逆方向のデータ受け渡しでは8グループと各itemsを保持できるが、おしゃべりnote固有のfavoriteGroupDisplayをひきこもりnoteのmodeへ反映するかは受取側の実装による。ひきこもりnoteは変更していない。
